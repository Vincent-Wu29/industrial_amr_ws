# M4 预登记实验 v2

2026-10-27，在正式 A/B 采样前修订。原假设保留在 protocol_v1.md；未采集过正式 A/B 样本。

M3 实测发现本机在目标实时因子 3 下运行 DWB 完整足迹评价时，20 Hz 控制循环出现约 8–13 Hz 的超时告警，实际 RTF 约 1.7–2.3。尚无证据证明狭窄通道存在震荡，因此本轮检验较短轨迹预测是否减少控制器计算负担、缩短墙钟运行时间；不宣称算法路径质量提高。

- 场景：narrow_aisle，通道 x=8–12 m、y=12.0–12.8 m，净宽0.8m；底盘碰撞包络0.40×0.30m，local/global padding=0.12m，inflation_radius=0.55m。
- 过程：HOME → (7,12.4) → (7.5,12.4)；正式计时段 (7.5,12.4) → (12.5,12.4)，朝向0。必须有通道内部真值样本，走绕行路线不能作为穿越成功。
- Baseline：版本化 nav2.yaml，Navfn+DWB，sim_time=1.7s，保留完整 ObstacleFootprint 评价。
- Candidate：唯一差别为 DWB sim_time=1.2s；采样数、对齐权重、足迹、速度/加速度、代价地图、恢复与目标均相同。较短预测可能减少碰撞评价次数，也可能降低提前避障能力，必须做关键故障回归。
- 主要指标：成功计时段墙钟耗时 P95，目标下降≥15%。同时报告仿真耗时、控制器CPU秒、实际RTF、成功率与通道物理最小间隙；仿真P95不得增加超过5%，两组成功率不得下降、碰撞为0、真值有效。
- 样本：每组30次，配对种子42–71，串行、每次新建独立世界、同一机器、相同目标RTF3。最终报告保留所有失败样本；种子不能控制AMCL和线程调度的全部差异。
- 执行次序：先完成M3安全基线，再依次采Baseline与Candidate；不得根据结果修改候选或主要指标。若有程序缺陷使实验无效，记录原因并整组重新采集，旧数据保留。
- P95采用排序后第ceil(0.95N)项，同时报告N、均值、中位数；缺终态为中断，不计成功。
- 产物：manifest/有效参数与源码哈希、原始系统日志、真值、物理障碍轨迹、每次metrics.json、组报告；比较命令显式 `metrics_report --metric wall`。
- 未达提升门槛、仿真耗时退化、安全或样本不足时如实报告候选不成立/证据不足。墙钟吞吐改善仅适用于本机仿真计算条件，不能表述成机器人实际作业速度提高。
